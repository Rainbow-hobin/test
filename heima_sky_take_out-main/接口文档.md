# 苍穹外卖（Sky Takeout）接口文档

> 版本：2.0　|　生成日期：2026-08-10
> 后端项目：`heima_sky_take_out-main/sky-server`（Spring Boot 2.x + MySQL + Redis + 阿里云 OSS + 微信支付）

> ⚠️ **网页版改造说明（2026-08-20）**：本项目已复刻为网页版并移除微信相关代码。
> - 微信登录 → 账号密码登录（`POST /user/user/login`，请求体 `username/password/role`，role：1用户 2商家）
> - 新增 `POST /user/user/register` 注册接口
> - 微信支付/回调 → 点击支付即模拟付款成功（`PUT /user/order/payment` 直接置为已支付）
> - 新增 `PUT /user/order/cancel/{id}` 用户取消订单
> - 新增商家端接口 `/merchant/**`（订单分页、统计、接单、派送、完成）
> - 数据库改为 `sky_web`；`user` 表为 `username/password/role`
> - 店铺状态与菜品缓存改为内存实现，不再依赖 Redis；菜品图片为本地占位图

## 1. 基本信息

| 项目 | 值 |
| --- | --- |
| 服务端口 | `8080` |
| 基础地址 | `http://localhost:8080` |
| 数据库 | `sky_take_out`（MySQL，端口 3307） |
| 缓存 | Redis（默认 localhost:6379，用于店铺状态、菜品缓存） |
| 在线文档 | Knife4j/Swagger：`http://localhost:8080/doc.html` |

接口按端分为两组：

- **管理端**（B 端后台，`/admin/**`）：员工、分类、菜品、套餐、订单、店铺、报表、工作台、文件上传。
- **用户端**（C 端小程序，`/user/**`）：微信登录、分类、菜品、套餐、购物车、订单、地址簿、支付回调。

## 2. 通用说明

### 2.1 统一返回结构 `Result<T>`

所有接口（除文件下载、支付回调外）均返回以下 JSON 结构：

```json
{
  "code": 1,
  "msg": null,
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | `1` 成功；`0` 失败 |
| `msg` | String | 失败时的错误提示，成功为 `null` |
| `data` | T | 业务数据，无数据时为 `null` |

> 注意：业务失败时 HTTP 状态码仍为 200，通过 `code=0` 和 `msg` 区分；JWT 校验不通过时返回 HTTP `401`。

### 2.2 分页结构 `PageResult<T>`

```json
{
  "code": 1,
  "msg": null,
  "data": {
    "total": 100,
    "records": []
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | long | 总记录数 |
| `records` | List\<T\> | 当前页数据 |

### 2.3 鉴权方式

| 端 | 请求头 | 说明 |
| --- | --- | --- |
| 管理端 | `token` | 除 `POST /admin/employee/login` 外，`/admin/**` 全部需要 |
| 用户端 | `authentication` | 除 `POST /user/user/login` 外，`/user/**` 全部需要 |

Token 为登录接口返回的 JWT。校验失败返回 HTTP `401`。

## 3. 管理端接口（/admin）

### 3.1 员工管理 `/admin/employee`

#### 3.1.1 员工登录（无需鉴权）

- **POST** `/admin/employee/login`

请求体 `EmployeeLoginDTO`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | String | 是 | 用户名 |
| `password` | String | 是 | 密码（MD5 加密后比对） |

响应 `data`（`EmployeeLoginVO`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Long | 员工主键 |
| `userName` | String | 用户名 |
| `name` | String | 姓名 |
| `token` | String | JWT 令牌（后续请求头 `token` 使用） |

失败提示：`账号不存在` / `密码错误` / `账号被锁定`。

#### 3.1.2 新增员工

- **POST** `/admin/employee`

请求体 `EmployeeDTO`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | Long | 否 | 主键（新增不传） |
| `username` | String | 是 | 用户名（唯一） |
| `name` | String | 是 | 姓名 |
| `phone` | String | 否 | 手机号 |
| `sex` | String | 否 | 性别 |
| `idNumber` | String | 否 | 身份证号 |

说明：新增后状态默认为启用，密码默认为 `123456`（MD5 存储）；用户名重复返回 `账号已存在`。

#### 3.1.3 员工分页查询

- **GET** `/admin/employee/page`

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | String | 否 | 员工姓名（模糊查询） |
| `page` | int | 是 | 页码，从 1 开始 |
| `pageSize` | int | 是 | 每页条数 |

响应：`PageResult<Employee>`，记录字段见 [Employee](#employee员工)。

#### 3.1.4 启用/禁用员工

- **GET** `/admin/employee/status/{status}?id=`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `status`（路径） | Integer | `1` 启用，`0` 禁用 |
| `id`（Query） | Long | 员工 ID |

#### 3.1.5 根据 ID 查询员工

- **GET** `/admin/employee/{id}`

响应：`Result<Employee>`。

#### 3.1.6 修改员工

- **PUT** `/admin/employee`

请求体同 [3.1.2 新增员工](#312-新增员工)（需传 `id`）。

#### 3.1.7 员工退出

- **POST** `/admin/employee/logout`

服务端不维护会话，直接返回成功。

### 3.3 菜品管理 `/admin/dish`

#### 3.3.1 新增菜品

- **POST** `/admin/dish`

请求体 `DishDTO`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | Long | 否 | 主键（新增不传） |
| `name` | String | 是 | 菜品名称 |
| `categoryId` | Long | 是 | 分类 ID |
| `price` | BigDecimal | 是 | 价格 |
| `image` | String | 是 | 图片 URL |
| `description` | String | 否 | 描述 |
| `status` | Integer | 否 | `0` 停售，`1` 起售 |
| `flavors` | List\<DishFlavor\> | 否 | 口味列表（见 [DishFlavor](#dishflavor菜品口味)） |

#### 3.3.2 菜品分页查询

- **GET** `/admin/dish/page`

Query 参数：`page`、`pageSize`（必填），`name`、`categoryId`、`status`（可选）。

> ⚠️ 注意：服务端会强制把 `pageSize` 改为 `100000`，此接口实际返回全部菜品。

响应：`PageResult<DishVO>`。

#### 3.3.3 启用/停用菜品

- **POST** `/admin/dish/status/{status}?id=`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `status`（路径） | Integer | `1` 启用，`0` 停用 |
| `id`（Query） | Long | 菜品 ID |

> ⚠️ 注意：当前 `DishServiceImpl.startOrStop()` 实现为空，此接口调用后**不会真正修改状态**，仅清理 Redis 菜品缓存。

#### 3.3.4 批量删除菜品

- **DELETE** `/admin/dish?ids=1,2,3`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `ids` | Long[] | 菜品 ID 数组（逗号分隔） |

说明：起售中的菜品不能删除（`起售中的菜品不能删除`）；已被套餐关联的不能删除（`当前菜品关联了套餐,不能删除`）。

#### 3.3.5 根据 ID 查询菜品

- **GET** `/admin/dish/{id}`

响应：`Result<DishVO>`（含口味列表）。

#### 3.3.6 修改菜品

- **PUT** `/admin/dish`

请求体同 [3.3.1](#331-新增菜品)（需传 `id`；口味会先删后插）。

#### 3.3.7 根据分类查询菜品

- **GET** `/admin/dish/list?categoryId=`

响应：`Result<List<Dish>>`。

## 7. 已知问题与注意事项

以下为本项目当前代码中需要注意的问题（生成文档时从源码核对）：

1. **`/user/shop/status` 无后端实现**：`WebMvcConfiguration` 中该路径已被放行（不校验 JWT），但 `com.sky.controller.user` 下没有对应的 ShopController，前端调用会 404；`/admin/shop/*` 仅管理端可用。
2. **管理端菜品启停未生效**：`POST /admin/dish/status/{status}` 调用的 `DishServiceImpl.startOrStop()` 方法体为空，接口返回成功但状态不会改变。
3. **管理端批量删除套餐未生效**：`DELETE /admin/setmeal` 调用的 `SetmealServiceImpl.deleteBatch()` 方法体为空，不会删除任何数据。
4. **菜品分页接口强制 pageSize**：`GET /admin/dish/page` 服务端将 `pageSize` 固定为 `100000`，分页参数实际不生效。
5. **外部依赖配置为空**：`application-dev.yml` 中阿里云 OSS（`sky.alioss.*`）、微信小程序/支付（`sky.wechat.*`）均为空字符串，文件上传、微信登录、微信支付相关接口需先配置才能使用。
6. **依赖 Redis**：店铺状态（`SHOP_STATUS`）与菜品缓存（`dish_*`）存储在 Redis 中，Redis 未启动时相关接口会报错；`application.yml` 中 Redis 端口为 `6379`。
7. **数据库初始化**：`sky_take_out.sql` 仅含表结构（无 `CREATE DATABASE` 与初始数据），需先执行 `CREATE DATABASE sky_take_out ...` 再导入；`employee` 表为空时管理端无法登录，需手动插入一条账号（密码为 MD5 值）。
